Features

The Hypercore README lists five features. Each is shown here with something you can run or read.

Sparse replication

The README says you only download the data you are interested in. What to look for below: the reader ends up holding block 3 but not block 0. In this run a reader asks for block 3 of five, and ends up holding block 3 but not block 0.

Realtime

The README says you get the latest updates to the log fast and securely. This site has not timed it. A core emits append when its length changes, locally or from a peer, and download when a block arrives. The run above prints one download event.

Performant

The README says Hypercore uses a simple flat file structure to maximize I/O performance. This site has not benchmarked it. Version 11 keeps data in hypercore-storage, and the README notes that random-access-storage is no longer supported.

Secure

The README says Hypercore uses signed Merkle trees to verify the log's integrity in real time. Reading the installed source confirms the parts: leaves and parents are hashed with BLAKE2b (crypto_generichash), the root hashes are hashed together, and that result is signed with the core's key pair (crypto_sign_detached).

Modular

The README says Hypercore aims to do one thing and do it well: distribute a stream of data. Finding peers and managing many cores are left to other modules; the README points to Hyperswarm and Corestore.
