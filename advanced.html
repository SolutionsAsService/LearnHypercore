Advanced topics

What happens beyond append and get. Each topic names its source: the README, the installed code, or a run.

Truncate and forks

core.truncate(newLength) shortens the core. By default it raises the core's fork id by one; you can pass the fork id you prefer, but it should only increase. The core emits a truncate event, locally or when a peer truncates. In the run below the fork id goes from 0 to 1.

Sessions and snapshots

core.session() makes a new instance that shares the same underlying core; you must close every session you make. core.snapshot() is the same, backed by a storage snapshot, so it will not append or truncate. In the run above the snapshot stays at length 3 while the core grows to 4.

The README also describes atoms, which let sessions make atomic changes across several cores. We have not run an atom example here, so read it in the README before relying on it.

Block encryption

Pass encryption: { key } with a 32-byte key and blocks are stored encrypted; get decrypts them. Keep the key: the example generates a random one, so the data is unreadable on a later run. core.padding is 0 unless block encryption is on.

Replication and finding peers

core.replicate(isInitiator) returns a stream you pipe to another core's stream; one side is the initiator, the other is not. Over a network you pipe sockets. The README names Hyperswarm as the usual way to find peers, and Corestore for managing many cores. core.discoveryKey is what you announce, because it does not reveal the key that verifies the data. The replication example shows two cores in one process.

Storage

Give the constructor a directory. You can also pass a Hypercore Storage instance or use a Corestore. random-access-storage is no longer supported, so older tutorials that pass a storage function will fail.

Block size

The suggested maximum block size is Hypercore.MAX_SUGGESTED_BLOCK_SIZE, 15 MB, so blocks replicate smoothly. For larger data, append many blocks.
