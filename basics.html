The basics

Hypercore is a secure, distributed append-only log, built for sharing large datasets and streams of real-time data.

A log of numbered blocks

Think of a receipt roll: you can add to the end, but you cannot slip a new receipt into the middle. A Hypercore, usually called a core, is a list of blocks like that. Each block is a chunk of bytes you chose: a message, a row, a slice of a file. Blocks are numbered from 0 in the order they were added, and core.length says how many there are. You add to the end with core.append().

Words you will meet

These are used on the rest of the site, so they come first.

WordMeaning
blockOne entry in the log. Read it with core.get(index).
keyThe public key that identifies a core. Anyone who has it can read and verify the core. core.key
discovery keyA key derived from the public key. It finds peers without revealing the key that verifies the data. core.discoveryKey
writableWhether you hold the key pair that lets you append. A reader that has only the public key is not writable.
forkA counter that goes up when a core is truncated. It starts at 0.
peerAnother copy of the core you are connected to.
hashA short fingerprint of some data. Change one byte of the data and the fingerprint changes completely.
rootThe fingerprint of a whole branch of blocks, made by hashing smaller fingerprints together. A log has one or more roots.
signatureProof, made with the core's secret key, that the roots are the writer's. Anyone with the public key can check it.
truncateCut a core back to a shorter length. The fork id goes up so peers can tell the history changed.

How a reader trusts a block

Every block is hashed. Hashes are combined in pairs, up a tree, into a small set of root hashes, and the roots are signed by the core's key pair. A reader that has the public key can check any block it receives against the signed roots, using a few hashes from the tree instead of the whole log. The home page lets you build that tree and watch it work.

What "append-only" does and does not mean

Blocks are not edited in place. You add at the end. The API does let a writer truncate a core to a shorter length, which raises the fork id, and anyone can clear blocks from their own local copy to save space. So the guarantee is not that data can never disappear from a machine. It is that what a reader accepts has been verified against the signed roots.
